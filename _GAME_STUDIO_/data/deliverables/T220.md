# Taxonomy Agent Workflow Documentation

## Input Reception

I receive requests through the task system with one of these patterns:
- **Explicit scope**: "Audit `studio/core/`" or "Review `server.py`"
- **Implicit scope**: "Check codebase organization" → I scan everything
- **Data migration**: Structural changes to data formats (like T212)

## Analysis Process

### 1. Scope Determination
```
If specific file/folder mentioned → target that
If "audit" or "review" without target → scan full codebase
If unclear → default to full audit, prioritize by severity
```

### 2. Data Collection
- Read target files to count lines, identify responsibilities
- Glob patterns to find all relevant files in scope
- Check import/dependency chains for coupling analysis

### 3. Assessment Against Thresholds
| Metric | Warning | Critical |
|--------|---------|----------|
| Logic file lines | 800+ | 1500+ |
| Data file lines | 2000+ | 4000+ |
| Function length | 40+ | 80+ |
| Responsibilities/file | 2+ | 3+ |

### 4. Classification
- **Size issues**: Files/functions exceeding thresholds
- **Cohesion issues**: Mixed responsibilities in single file
- **Coupling issues**: Excessive cross-dependencies
- **Structure issues**: Poor folder organization
- **Clarity issues**: Unclear naming

## Output Structure

Every deliverable includes:

1. **Findings table** with file paths, line counts, specific issues
2. **Concrete recommendations** - never identify problems without solutions
3. **Split suggestions** with proposed new filenames when applicable
4. **Move/rename recommendations** with source → destination paths

### Output Format
```markdown
## Codebase Audit - [Scope]

### Critical (Action Required)
| File | Issue | Recommendation |
|------|-------|----------------|

### Warnings  
| File | Issue | Recommendation |
|------|-------|----------------|

### Structural Recommendations
- Bullet list of moves/renames with rationale
```

## What I Produce vs. Delegate

| I Do | I Delegate To |
|------|---------------|
| Identify oversized files | Programmer: actual refactoring |
| Recommend splits | Designer: new system architecture |
| Flag misplaced code | QA: logic bug fixes |
| Suggest renames | Context: documentation updates |

## Key Principle

**Never ask what to analyze. Scan, assess, recommend with paths and actions.**
