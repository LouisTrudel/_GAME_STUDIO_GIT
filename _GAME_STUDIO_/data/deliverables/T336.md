# 5-Phase Spec-to-Ship Workflow: UX Design Report

## Executive Summary

Design a minimal-click UI where users see progress without managing it. The 5 phases should feel like one continuous action with transparent progress, not 5 separate steps.

---

## The 5 Phases

| # | Phase | System Action | User Action |
|---|-------|--------------|-------------|
| 1 | Submit | User writes spec | Write + Submit (1 click) |
| 2 | Decompose | BOSS creates tasks | Watch (0 clicks) |
| 3 | Execute | Agents work in parallel | Watch (0 clicks) |
| 4 | Validate | QA runs checks | Watch (0 clicks) |
| 5 | Deliver | Output assembled | Review + Accept (1 click) |

**Total user clicks: 2** (Submit, Accept)

---

## Phase Progression Visual Design

### Option A: Linear Pipeline Bar (Recommended)

```
┌──────────────────────────────────────────────────────────────────┐
│  [●] SPEC → [●] DECOMPOSE → [◐] EXECUTE → [ ] QA → [ ] DELIVER  │
│       ✓         ✓            3/7                                │
└──────────────────────────────────────────────────────────────────┘
```

| Symbol | Meaning |
|--------|---------|
| [ ] | Pending |
| [◐] | In progress (animated) |
| [●] | Complete |
| [!] | Blocked/Error |

**Placement:** Horizontal bar below header, always visible during active job.

**Behavior:**
- Appears when spec submitted
- Each phase lights up as it begins
- Shows count (3/7 tasks) during Execute phase
- Collapses to "✓ Delivered" after completion

### Option B: Vertical Timeline (Alternative)

```
● Spec submitted          2:34 PM
│
● BOSS decomposed → 5 tasks   2:34 PM
│
◐ Executing...           2:35 PM
  ├─ Designer: Done
  ├─ Programmer: Working
  └─ Artist: Queued
│
○ QA validation
│
○ Delivery
```

**Trade-off:** More detail, more screen space. Better for debugging, worse for simplicity.

**Recommendation:** Option A for main view. Option B available on click/expand.

## Phase Details: What User Sees at Each Step

### Phase 1: Submit Spec

**Current state:** Text input + Send button

**Enhanced UX:**
- Same text input (don't change what works)
- Add visual hint: "Describe what you want built..."
- On submit: Input clears, pipeline bar appears with Phase 1 lit

**Click count:** 1

### Phase 2: BOSS Decomposes

**What happens:** BOSS analyzes spec, creates task tree

**What user sees:**
```
┌─────────────────────────────────────────┐
│ BOSS is analyzing your spec...          │
│                                         │
│ Creating tasks:                         │
│   ✓ T127: Design coin economy          │
│   ✓ T128: Implement coin manager       │
│   + T129: Create coin UI sprite        │
│     ...creating                        │
└─────────────────────────────────────────┘
```

**Behavior:**
- Tasks appear as BOSS creates them
- Subtle animation for each new task
- Auto-transitions to Execute when done

**Click count:** 0

### Phase 3: Agents Execute

**What happens:** Specialist agents work on assigned tasks

**What user sees:**
```
┌─────────────────────────────────────────┐
│ Executing (3/7 tasks complete)          │
│                                         │
│ ✓ T127: Economy design      Designer    │
│ ◐ T128: Coin manager        Programmer  │
│ ◐ T129: Coin sprite         Artist      │
│ ○ T130: Shop UI             Designer    │
│ ...                                     │
└─────────────────────────────────────────┘
```

**Behavior:**
- Task list sorted: in_progress at top, then pending, completed at bottom
- Click task to expand and see agent output
- Progress bar or fraction shows overall completion
- Auto-transitions to QA when all tasks complete

**Click count:** 0 (optional clicks to inspect)

### Phase 4: QA Validates

**What happens:** QA agent reviews outputs, runs checks

**What user sees:**
```
┌─────────────────────────────────────────┐
│ QA validating outputs...                │
│                                         │
│ ✓ Files exist check                     │
│ ✓ Code syntax check                     │
│ ◐ Running integration test...           │
└─────────────────────────────────────────┘
```

**Behavior:**
- Shows QA checklist items
- If bug found: Creates bug task, loops back to Execute
- Visual indicator when bug-fix loop occurs

**Click count:** 0

### Phase 5: Deliver

**What happens:** All work assembled, ready for user

**What user sees:**
```
┌─────────────────────────────────────────┐
│ ✓ DELIVERED                             │
│                                         │
│ Coin Economy System                     │
│                                         │
│ Deliverables:                           │
│   📄 coin-economy-spec.md               │
│   📦 CoinManager.js                     │
│   🎨 coin-sprite.png                    │
│   📄 integration-notes.md               │
│                                         │
│ [View Details]  [Open in Explorer]      │
└─────────────────────────────────────────┘
```

**Behavior:**
- List all deliverable files with icons by type
- Click to preview, open folder, or view full report
- Pipeline bar collapses after user acknowledges

**Click count:** 1 (acknowledge/dismiss)

## Phase Transitions: Automatic vs Manual Gates

| Transition | Type | Rationale |
|------------|------|-----------|
| Submit → Decompose | Auto | User intent already expressed |
| Decompose → Execute | Auto | No decision needed |
| Execute → QA | Auto | Natural flow |
| QA → Deliver (pass) | Auto | Success case |
| QA → Execute (bugs) | Auto | Bug-fix loop |
| Deliver → Done | Manual | User must acknowledge receipt |

**Manual gate at delivery only.** User says "I got it" before we consider job done.

**Optional:** Add "Auto-approve" toggle (already exists in UI) to auto-dismiss deliveries too.

---

## Error States

| Error | Visual | User Action |
|-------|--------|-------------|
| BOSS can't decompose | Red banner: "Could not understand spec" | Reword and resubmit |
| Agent stuck | Task shows ⚠️, "Stuck: [reason]" | Click to see details, manually resolve |
| QA fails repeatedly | Red loop indicator | Review failures, adjust spec |
| Delivery blocked | "Incomplete: 2 tasks failed" | Click to see blockers |

## Implementation Priorities

### Phase 1: MVP (Minimum Viable Pipeline)
1. Add pipeline status bar to Hub view
2. Show phase transitions in real-time via WebSocket
3. Basic task list during Execute phase
4. Delivery summary view

### Phase 2: Polish
1. Expandable timeline view (Option B)
2. Per-task progress animation
3. QA checklist visualization
4. Deliverable file preview

### Phase 3: Power User
1. Pause/cancel job mid-execution
2. Skip QA toggle
3. Partial delivery (ship what's done)
4. Job history/replay

## Summary

The 5-phase workflow should feel like ordering food delivery:

1. **Order** (submit spec)
2. **Restaurant prepares** (decompose + execute) — watch tracker
3. **Quality check** (QA) — automatic
4. **Delivered** (accept delivery)

User controls the start and acknowledges the end. Everything in between is visible but requires no action. Simplicity is the feature.
