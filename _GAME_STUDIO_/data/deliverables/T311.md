## Deliverable

**T311 Fix: Dual narrative systems producing duplicate history files**

### Root Cause
Both T282 (`_generate_history_narrative`) and T309 (`_generate_tier_narrative`) were active via separate callbacks. When memory compressed, both ran and saved files with different naming patterns:
- T282: `{date}_epoch{tier}_{count}.md` (e.g., `2026-09-07_epoch0_1.md`)
- T309: `{prefix}_{date}_{count}.md` (e.g., `draft_2026-09-07_1.md`)

### Solution
Deprecated T282 in favor of T309. T309's tiered system (Draft → Chapter → Book → Collection) is more sophisticated and should handle all history narratives.

### Changes Made

**studio/studio.py:**
- Removed `set_history_callback()` call from `__init__` (line 71)
- Removed entire `_generate_history_narrative()` method (~55 lines)
- Added deprecation comment explaining T282 was replaced by T309

**studio/core/memory.py:**
- Removed `HistoryNarrativeCallback` type alias
- Removed `_history_callback` instance variable
- Removed `set_history_callback()` method
- Removed `_generate_history_narrative()` method (~35 lines)
- Removed call to `_generate_history_narrative()` in `compress_tier()`
- Added deprecation comment in `compress_tier()`

### Result
Now only T309's tiered system runs on memory compression, producing a single narrative file per compression event with the correct tier-prefixed naming pattern (`draft_`, `chapter_`, `book_`, `collection_`).
