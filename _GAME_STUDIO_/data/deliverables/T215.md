=== context_injected Field ===

### Purpose
Track what context was injected into each task's agent prompt, enabling:
- Visibility: Prove what context each task received
- Debugging: Identify when wrong/missing context caused failures
- Optimization: Find which context sources consume most tokens

### Schema
```python
# New field on Task dataclass
context_injected: dict[str, int] = field(default_factory=dict)

# Example value:
{
    "role_md": 2847,           # role.md character count
    "skills": 15234,           # combined skills character count
    "context_md": 8921,        # CONTEXT.md character count
    "task_prompt": 342,        # trigger message character count
    "project_context": 4100,   # project-specific context if any
}
```

### Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Unit** | Characters | Tokens require tokenizer call (expensive). Chars are O(1) via `len()`. Estimate: tokens ≈ chars/4 |
| **Storage** | Task field | Not separate log. Tied to task lifecycle, simplifies queries |
| **When populated** | At execution (in `_run_agent_task`) | Context only known at dispatch time, not creation |
| **Granularity** | Source→size map | More useful than single total. Enables "which source was biggest?" |

### Implementation Location

### TaskManager Method

```python
def log_context_injected(self, task_id: str, context: dict[str, int]) -> bool:
    """Log character counts of each injected context source (T215)."""
    task = self.tasks.get(task_id)
    if task:
        task.context_injected = context
        self._save_tasks()
        return True
    return False
```

### Serialization

```python

```

### Edge Cases
| Case | Behavior |
|------|----------|
| Raw task (no agent) | Empty dict `{}` - no context injection |
| Agent missing method | Graceful `0` - `len(x or "")` pattern |
| Context changes mid-task | Snapshot at dispatch time only |
| Huge context (>100KB) | Logged as-is, no truncation (it's just a number) |

### Migration
- Default `{}` for existing tasks (backwards compatible)
- No migration needed - field is additive

### Success Criteria
- [ ] Every completed task has `context_injected` populated

- [ ] Overhead: <1ms per task (just `len()` calls)
- [ ] Archive size impact: ~50 bytes/task (negligible vs current ~2KB)
