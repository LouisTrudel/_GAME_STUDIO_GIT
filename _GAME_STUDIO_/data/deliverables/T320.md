# Per-Project CEO Agent Architecture

## Folder Structure

```
projects/
├── _registry.json              # List of all projects + active project ID
│
└── <project-name>/
    ├── CONTEXT.md              # Cross-agent signals (existing)
    ├── whitepaper.md           # Project vision, goals, constraints
    ├── roadmap.md              # Milestones, phases, current focus
    │
    ├── memory/
    │   ├── session.json        # Current session context (clears on switch)
    │   ├── short_term.json     # Recent decisions, last 7 days
    │   └── long_term.json      # Persistent learnings, patterns
    │
    ├── history/
    │   └── YYYY-MM-DD.json     # Daily conversation logs
    │
    └── ceo_config.json         # CEO personality, priorities, rules
```

## _registry.json Schema

```json
{
  "active_project": "my-game",
  "projects": [
    {
      "id": "my-game",
      "name": "My Awesome Game",
      "path": "projects/my-game",
      "external_path": "C:/Games/MyGame",
      "created": "2026-09-01",
      "last_accessed": "2026-09-07"
    }
  ]
}
```

## ceo_config.json Schema

```json
{
  "display_name": "CEO-MyGame",
  "personality": "focused on shipping MVP",
  "priorities": ["core loop", "performance", "player retention"],
  "rules": [
    "No feature creep until v1.0",
    "All assets under 2MB"
  ],
  "context_budget": {
    "whitepaper_lines": 50,
    "roadmap_lines": 30,
    "memory_tokens": 2000
  }
}
```

## CEO Prompt Template

```markdown
# CEO: {display_name}

You are the CEO of project "{project_name}".

## Your Project
{whitepaper summary - first N lines}

## Current Phase
{roadmap current milestone}

## Priorities
{priorities list from config}

## Rules
{rules list from config}

## Recent Context
{short_term memory - last 5 entries}

## Your Authority
- You own all decisions for THIS project
- You delegate work to the shared fleet (Designer, Programmer, Artist, Writer, QA)
- You do NOT access other projects' data
- You escalate to BOSS only for: budget changes, timeline >2 weeks slip, external dependencies

## Communication
- When delegating: specify project_id in all tool calls
- Fleet agents see only YOUR project's CONTEXT.md
- Your memory is isolated - other CEOs cannot read it
```

## Memory Isolation Rules

| Rule | Implementation |
|------|----------------|
| Session memory clears on project switch | `session.json` wiped when `active_project` changes |
| Short-term scoped to project | Stored in `projects/<id>/memory/short_term.json` |
| Long-term never crosses projects | Stored in `projects/<id>/memory/long_term.json` |
| Fleet agents receive project_id | All tool calls include `project_id` param |
| CONTEXT.md per project | Signals stay in `projects/<id>/CONTEXT.md` |
| History isolated | Logs go to `projects/<id>/history/` |

## Hub Integration

### Switching Mechanism

```
User Input: "switch to MyGame"
           or clicks project in Projects tab

Hub Action:
1. Save current session memory to active project
2. Update _registry.json.active_project
3. Clear global session state
4. Load new CEO prompt from target project
5. Load target project's session memory
6. Display: "Now talking to CEO-MyGame"
```

### UI Changes

| Location | Change |
|----------|--------|
| Header | Show current agent: "BOSS" or "CEO-{name}" |
| Projects tab | List all projects, highlight active |
| Quick switch | Dropdown in header for fast switching |
| Chat input | Prefix shows context: `[CEO-MyGame] >` |

### Command Support

```
/switch <project-name>    # Switch to project's CEO
/boss                     # Return to BOSS (studio-wide)
/projects                 # List all projects
/project info             # Show current project details
```

## CEO ↔ Fleet Communication

### Delegation Flow

```
CEO-MyGame                          Fleet (Singleton)
    │                                     │
    ├─── "Implement coin system" ────────►│
    │    (includes project_id)            │
    │                                     │
    │                                Programmer loads:
    │                                - projects/my-game/CONTEXT.md
    │                                - my-game whitepaper (if needed)
    │                                - my-game specific skills
    │                                     │
    │◄─── Result + signals ───────────────┤
    │    (written to my-game/CONTEXT.md)  │
```

### Tool Call Modifications

All fleet tool calls require `project_id`:

```json
{
  "tool": "signal_agent",
  "params": {
    "project_id": "my-game",
    "to_agent": "Programmer",
    "message": "Coin system uses 3 tiers"
  }
}
```

### Context Injection

When fleet agent starts task:
1. Read `projects/{project_id}/CONTEXT.md`
2. Optionally read whitepaper if task needs vision context
3. Write signals back to same CONTEXT.md
4. Never access other project folders

## BOSS vs CEO Permissions

| Action | BOSS | CEO |
|--------|------|-----|
| Create new project | ✓ | ✗ |
| Delete project | ✓ | ✗ |
| Access all projects | ✓ | ✗ (own only) |
| Modify studio config | ✓ | ✗ |
| Delegate to fleet | ✓ | ✓ |
| Access external APIs | ✓ | ✓ (own scope) |
| Budget decisions | ✓ | ✗ (escalate) |

## Edge Cases

| Scenario | Behavior |
|----------|----------|
| Switch during active task | Warn user, offer to wait or abandon |
| Fleet task spans projects | Block - one project per task |
| CEO references other project | Respond "I don't have access to that project" |
| Project deleted while active | Switch to BOSS, notify user |
| No projects exist | BOSS only, Projects tab shows "Create first project" |
