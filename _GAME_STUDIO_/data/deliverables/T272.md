## Deliverable: T272 - Migrate remaining code to AC-Memory model

### Summary

Migrated all context handling to the unified AC-Memory (Accumulated Compacted Memory) tiered compression model. AC-Memory provides infinite compression capability: Tier N's `accumulated_a` gets compressed to `summary_b`, which chains to Tier N+1's `accumulated_a`.

### Changes Made

#### 1. `studio/agents/boss/tools.py` - recall_memory()
**Before:** Used deprecated methods `get_hot_entries()` and `search(query, tiers=[...])` that don't exist in AC-Memory.

**After:** Uses AC-Memory methods:
- `memory_manager.get_recent(tier_index=0)` for empty queries
- `memory_manager.search(query, max_tiers=5)` for keyword searches
- Updated schema description to reflect AC-Memory tier model

#### 2. `studio/core/hub.py` - Session summary removal
**Before:** Had `session_summary` in-memory variable and `summarize_old_messages()` that duplicated AC-Memory functionality.

**After:**
- Removed `session_summary` in-memory variable
- Updated `get_context_for_agent()` to fallback to AC-Memory's Tier 0 instead of deprecated `session_summary`
- Marked `summarize_old_messages()` as deprecated - now only trims messages, AC-Memory handles compression

#### 3. Preserved compatibility
- `tasks.py:63` uses `memory_manager.add_hot()` - this is a legacy wrapper that correctly maps to `append_to_tier(0, ...)`
- `hub.py` still reads `session_memory.md` as primary source (Context agent writes this)
- AC-Memory's `_accumulate_to_tier0()` in hub.py continues to feed the compression chain

### Context Flow (Post-Migration)

```
Hub message → _accumulate_to_tier0() → Tier 0 accumulated_a
                                              ↓ (threshold exceeded)
                                        compress → Tier 0 summary_b
                                              ↓
                                        Tier 1 accumulated_a → ... → Tier N
```
