# Design Spec: Discuss Action for Learning Tab Suggestions

## Mechanic

Click "Discuss" → Parallel fetch Boss opinion + Research report → Display both in modal → User decides Approve/Reject

## UI Wireframe

### Suggestion Card (Updated)
```
┌─────────────────────────────────────────┐
│ [Suggestion Title]                      │
│ [Description text...]                   │
│                                         │
│ [Approve] [Reject] [Discuss]            │
└─────────────────────────────────────────┘
```

### Discussion Modal
```
┌─────────────────────────────────────────────────────┐
│ Discussing: [Suggestion Title]              [X]     │
├─────────────────────────────────────────────────────┤
│ ┌─────────────────────┐ ┌─────────────────────┐     │
│ │ BOSS OPINION        │ │ RESEARCH FINDINGS   │     │
│ │ ─────────────────── │ │ ─────────────────── │     │
│ │ [Loading...]        │ │ [Loading...]        │     │
│ │ or                  │ │ or                  │     │
│ │ [Opinion text with  │ │ [Fresh research     │     │
│ │  context/memory     │ │  report on topic]   │     │
│ │  based reasoning]   │ │                     │     │
│ │                     │ │                     │     │
│ │ Confidence: 85%     │ │ Sources: 3 analyzed │     │
│ └─────────────────────┘ └─────────────────────┘     │
│                                                     │
│           [Approve]  [Reject]  [Keep Pending]       │
└─────────────────────────────────────────────────────┘
```

| Param | Value | Notes |

| Max response length | 500 chars | Per column, truncate with "Show more" |
| Loading timeout | 30s | Per request, show error after |
| Button debounce | 500ms | Prevent double-click |

## API Endpoint Design

### POST `/api/suggestions/{id}/discuss`

**Request:**
```json
{
  "suggestion_id": "string"
}
```

**Response:**
```json
{
  "suggestion_id": "string",
  "boss_opinion": {
    "status": "loading" | "complete" | "error",
    "content": "string",
    "confidence": 0.0-1.0,
    "reasoning_sources": ["memory", "context"]
  },
  "research_report": {
    "status": "loading" | "complete" | "error", 
    "content": "string",
    "sources_analyzed": number,
    "key_findings": ["string"]
  }
}
```

**Alternative: SSE streaming endpoint**
```
GET /api/suggestions/{id}/discuss/stream
```
Returns events as each response completes.

## Edge Cases

| Case | Behavior |
|------|----------|
| Boss timeout | Show "Opinion unavailable" + allow decision anyway |
| Research timeout | Show "Research pending" + allow decision anyway |
| Both fail | Show error toast, keep suggestion in original state |
| User closes modal | No state change, can re-open |
| Suggestion already discussed | Cache results for 1 hour, show cached |

## State Transitions

```
suggestion.status: "pending" → "discussing" → "pending"
                                           → "approved"
                                           → "rejected"
```

## Success Criteria

- Modal loads within 500ms of click (UI frame)
- Both responses return within 30s (95th percentile)
- User can always Approve/Reject even if one source fails
- Existing Approve/Reject flow unchanged when Discuss not clicked

## Implementation Notes for Programmer

1. Add `discuss` button to suggestion card component
2. Create modal component with 2-column responsive layout
3. Implement parallel API calls using `Promise.allSettled`
4. Add loading spinners per column (independent)
5. Cache discussion results in frontend state
6. Backend: spawn Boss + Research agents in parallel threads/tasks
