# Boss Context Compaction Strategy

**CRITICAL: Task description is the ONLY context employees receive. If it's not in the task, it doesn't exist for the employee.**

## Include vs Exclude

| INCLUDE | EXCLUDE |
|---------|---------|
| Final decisions (not deliberation) | How we got there |
| Specific values/names/paths | "As discussed" references |
| Acceptance criteria | User's emotional state |
| File locations if known | Alternative approaches rejected |
| Error messages verbatim | Successful operations already complete |

## Compression Rules

### 1. Decision Extraction
**Before:** "User said they tried X, then Y, we discussed Z might work, they prefer Z because of reasons A and B"
**After:** "Use Z approach"

### 2. Scope Binding
**Before:** "We've been talking about improving the task system and the user wants better descriptions"
**After:** "[WHAT] Add priority field to task schema [FILE] studio/core/tasks.py"

### 3. Reference vs Inline Decision
| Condition | Action |
|-----------|--------|
| Prior task output needed | "See T### result" + 1-line summary |
| Prior task just context | Inline the relevant fact only |
| Dependency chain | "Requires T### completion first" |

### 4. Verbosity Collapse
- 3+ messages on topic → 1 sentence max
- Questions resolved → state answer only
- Debugging history → state root cause only

## Template

```
[WHAT] {verb} {noun} {scope}
[CONTEXT] {why this matters} | {key constraint}
[FILES] {paths if known}
[ACCEPT] {how to verify done}
```

## Anti-Patterns

❌ "As we discussed..." → Employee wasn't there
❌ "The user wants..." → Just state the requirement  
❌ "Similar to T###..." → Inline what's similar
❌ "See conversation..." → No access to conversation
❌ "Continue the work..." → Specify exact next step

## Examples

### Verbose → Compact

**Chat history (5 messages):** User reports button doesn't work, we check it's a click handler issue, user confirms they want it fixed, mentions it broke after last refactor, prefers minimal changes

**Bad task:** "Fix the button issue we discussed, user wants minimal changes, it broke recently"

**Good task:** "[WHAT] Fix submit button click handler [FILE] studio.js:handleSubmit [CONTEXT] Handler not bound after DOM update [ACCEPT] Button triggers form submission"

---

**Chat history (8 messages):** Long discussion about session memory format, multiple schema proposals, user settles on 3-section markdown

**Bad task:** "Implement the session memory format we agreed on after discussing options"

**Good task:** "[WHAT] Implement 3-section session memory: ##User Intent, ##Work Accomplished, ##Friction Events [CONTEXT] Replaces structured tool output [ACCEPT] Boss can read without parsing"

## Token Budget

Target: **50-150 tokens per task description**
- Under 50 = likely missing acceptance criteria
- Over 150 = likely includes deliberation noise
