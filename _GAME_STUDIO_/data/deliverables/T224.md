### Evidence-Based Recommendation

**Adopt Option B: Task-Recency Order**

```
1. tool schemas    (primacy - capabilities)
2. skills          (how to use tools)
3. role.md         (identity/constraints - middle)
4. context_md      (project context)
5. task trigger    (recency - action)
```

**Rationale from real task data:**

1. **T218 high_cost friction ($1.04)** - QA task spent excessive tokens re-reading context. Task-recency would frontload action.

2. **T212-T217 clean executions** - All had minimal context_md, task at end. Pattern works.

3. **Lost-in-middle effect**: role.md identity constraints are least critical for task execution (they're "who you are" not "what to do"). Moving to middle reduces compliance noise.

4. **Hub messages redundant**: Every archived task with `prompt_sent` shows task description duplicates RECENT MESSAGES info.
