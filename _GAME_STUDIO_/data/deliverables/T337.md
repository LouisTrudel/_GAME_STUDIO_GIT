# Information Architecture for 5-Phase Workflow

## Executive Summary

The salespitch outlines a 5-phase pipeline: **Spec Refinement → Multi-Agent Execution → QA Loop → Delivery**. This report analyzes how to architect data flows, phase awareness, gate structures, and UX surfacing for this workflow.

## 1. Data/Context Flows Between Phases

### Current State

| Data Store | Flow Direction | Contents |
|------------|----------------|----------|
| `tasks.json` | BOSS → Agents | Task queue, status, dependencies |
| `CONTEXT.md` | Agent ↔ Agent | Cross-agent signals, decisions, blockers |
| `memory/tier_*.json` | Accumulate → Compress | Session history via AB chaining |
| `messages.json` | Hub broadcast | Rolling 50-message buffer |
| `session_memory.md` | Context agent → All | Cumulative summary |

## 3. Benchmark/Gate Structure for Phase Transitions

### Gate Criteria Per Phase

| Phase → | Gate Criteria | Automated Check |
|---------|---------------|-----------------|
| Spec → Design | All spec tasks approved | `count(status=approved WHERE phase=spec) == count(phase=spec)` |
| Design → Impl | All design tasks approved + Designer sign-off | Above + CONTEXT.md flag |
| Impl → QA | Build succeeds + all impl tasks approved | Build script + task count |
| QA → Delivery | Zero P0/P1 bugs + coverage threshold | `qa_report.critical_count == 0` |
| Delivery → Done | Package created + release notes | File exists check |

### Gate Implementation

```python
# studio/core/gates.py
def check_gate(project_id: str) -> tuple[bool, str]:
    """Check if current phase gate criteria are met.
    
    Returns: (can_advance, reason)
    """
    project = project_manager.get(project_id)
    phase = project.phase
    
    if phase == "spec":
        # All spec tasks must be approved
        spec_tasks = get_tasks_by_phase(project_id, "spec")
        pending = [t for t in spec_tasks if t.status != "approved"]
        if pending:
            return False, f"{len(pending)} spec tasks still pending"
        return True, "Spec phase complete"
    
    # ... similar for other phases
```

### Phase Transition Flow

```
1. BOSS creates tasks tagged with current phase
2. Agents complete tasks
3. System checks gate periodically (or on task completion)
4. Gate pass → BOSS notified → Phase advances → Context updated
5. Gate fail → Blockers surfaced → No advance
```

## 4. UX Priority: What Users NEED to See vs Noise

### Current UI Components

| Component | Shows | User Value |
|-----------|-------|------------|
| Tasks sidebar | All active tasks | Medium (often cluttered) |
| Messages panel | Full agent chat | Low (too verbose) |
| Metrics bar | Token costs | Low (operational noise) |
| Activity bar | Agent avatars | Low (doesn't show progress) |

### Proposed: Phase-Centric Dashboard

**MUST SEE (Top of viewport, always visible):**
```
┌─────────────────────────────────────────────────┐
│ Phase: IMPLEMENTATION (3/5)  │ Progress: 7/12  │
│ ████████████░░░░░░ 58%       │ ETA: ~2 hours   │
│ Blockers: 0 │ Next gate: All impl tasks done   │
└─────────────────────────────────────────────────┘
```

**SHOULD SEE (Expandable panel):**
- Active tasks grouped by agent
- Recently completed tasks (last 5)
- Current agent activity (who's working)

**NOISE (Hidden by default, accessible via expansion):**
- Full message history
- Token costs per task
- Memory tier stats
- Compression logs

### Information Hierarchy

| Level | Content | Update Frequency | Display |
|-------|---------|------------------|---------|
| L1 Critical | Phase + blockers | On change | Always visible |
| L2 Progress | Task completion % | Every 30s | Always visible |
| L3 Activity | Which agents working | Every 5s | Compact bar |
| L4 Details | Individual tasks | On demand | Sidebar |
| L5 Debug | Tokens, memory | Never auto | Hidden tab |

### Phase Progress Calculation

```python
def calculate_phase_progress(project_id: str) -> dict:
    """Calculate phase completion metrics for UX."""
    project = project_manager.get(project_id)
    phase_tasks = get_tasks_by_phase(project_id, project.phase)
    
    total = len(phase_tasks)
    completed = len([t for t in phase_tasks if t.status == "approved"])
    blocked = len([t for t in phase_tasks if t.status == "blocked"])
    
    return {
        "phase": project.phase,
        "phase_number": PHASE_ORDER.index(project.phase) + 1,
        "total_phases": len(PHASE_ORDER),
        "tasks_total": total,
        "tasks_completed": completed,
        "tasks_blocked": blocked,
        "percent": int(completed / total * 100) if total else 0,
        "gate_status": check_gate(project_id),
    }
```
