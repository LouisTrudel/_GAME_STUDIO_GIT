```markdown
=== AB Chaining Memory Compression System ===

### Pattern

Each tier has two buffers:
- **[A] Accumulator**: Receives new data, appends until size threshold
- **[B] Condenser**: Compressed summary of A when A overflows

Flow: A fills → compress to B → B becomes next tier's A input

### Tier Definitions

| Tier | A Buffer | A Max Size | B Buffer | Trigger Location |
|------|----------|------------|----------|------------------|
| 0 (Hot) | messages[] | SMALL (20KB) | session_summary.md | After agent response |
| 1 (Warm) | appended_summaries[] | MEDIUM (100KB) | summary_of_summaries.md | After agent response |
| 2 (Cold) | old_summaries[] | LARGE (500KB) | archive_index.md | After agent response |

### Size Thresholds

| Constant | Value | Rationale |
|----------|-------|-----------|
| `TIER0_A_MAX_KB` | 20 | ~5000 tokens, fits in context |
| `TIER1_A_MAX_KB` | 100 | ~25k tokens, daily summaries |
| `TIER2_A_MAX_KB` | 500 | ~125k tokens, weekly/monthly |
| `COMPRESSION_RATIO` | 0.2 | Target 5:1 compression |

### Compression Trigger Logic

```python
def check_tier_compression(tier: int) -> bool:
    """Check if tier A buffer exceeds threshold."""
    thresholds = {0: 20, 1: 100, 2: 500}  # KB
    a_buffer_path = get_a_buffer_path(tier)
    if not a_buffer_path.exists():
        return False
    size_kb = a_buffer_path.stat().st_size / 1024
    return size_kb >= thresholds[tier]

def run_compression_cycle():
    """Triggered after every agent response in studio.py"""
    for tier in [0, 1, 2]:
        if check_tier_compression(tier):
            compress_tier(tier)
```

### Compression Operations

| Tier | A → B Compression | Output |
|------|-------------------|--------|
| 0 | LLM summarize messages | 2-3 paragraph session summary |
| 1 | LLM summarize summaries | Key decisions, outcomes, patterns |
| 2 | Keyword extraction + tagging | Searchable index (no LLM) |

### Data Flow Example

```
1. Agent responds → append to tier0/messages.json
2. tier0/messages.json > 20KB?
   YES → LLM compress → tier0/session_summary.md
       → append session_summary to tier1/appended_summaries.json
       → clear tier0/messages.json
       → save raw to logs/YYYY-MM-DD.json
3. tier1/appended_summaries.json > 100KB?
   YES → LLM compress → tier1/summary_of_summaries.md
       → append to tier2/old_summaries.json
       → clear tier1/appended_summaries.json
4. tier2/old_summaries.json > 500KB?
   YES → Extract keywords → tier2/archive_index.md (append)
       → clear tier2/old_summaries.json
```

### Edge Cases

| Case | Behavior |
|------|----------|
| Empty A buffer | Skip compression |
| LLM compression fails | Retry once, then truncate A to 80% |
| B file missing | Create empty B file |
| Concurrent access | File locking with fcntl/msvcrt |
| Tier 2 overflow | Append to archive_index.md indefinitely |

### Success Criteria

- [ ] Messages compressed 5:1 at each tier
- [ ] No data loss (logs/ always preserved)
- [ ] < 50ms overhead per tick
- [ ] Context agent retrieves from B buffers
- [ ] Compression runs server-side (mirrors hub chat pattern)
```

---

**Key Design Decisions:**

1. **Size-based triggers, not count-based** - More predictable for context windows
2. **LLM compression for tiers 0-1, keyword extraction for tier 2** - Diminishing returns on LLM for old data
3. **Same trigger location as hub chat** - After agent response in `_process_completed_futures()`
4. **Logs preserved separately** - Safety net, never compressed or deleted
5. **B buffer feeds next tier's A** - Clean cascade, no data duplication
