## T358 Deliverable: Prompt Structure Documentation

### Analysis

The task description is **inaccurate**. The skill system was NOT disabled in T365. What actually happened:
- **T356** added a `vanilla` flag for opt-out agents (CLAUDE)
- Standard agents (BOSS, Designer, Programmer, Artist, Writer, QA, etc.) **still receive full skill injection**

### Current Prompt Architecture (Accurate)

#### Standard Agents (vanilla=false, default)

**System Prompt Structure:**
```
## SKILLS
[Core tool skills from _tools/*.md]
[Shared skills from agents/shared/*.md]
[Agent-specific skills from agents/{name}/skills/*.md]

## ROUTER
[Router skill from skills/_routers/{type}.md]

## ROLE
[Role from agents/{name}/role.md]
```

**User Message Structure:**
```
## CONTEXT
[Dynamic task assignments, hub messages]

## TASK
[Trigger message]
```

#### Vanilla Agents (vanilla=true, e.g., CLAUDE)

**System Prompt:** Only `## ROLE` section (role.md content)
**User Message:** Raw trigger message only (no section wrappers)

### Position Effects (T224)

Prompt order is optimized for primacy/recency:
1. **SKILLS first** (primacy) - tools always accessible in context window
2. **ROLE last** (recency) - identity/constraints fresh in memory

### CONTEXT.md Purpose (Unchanged)

CONTEXT.md files in `projects/{id}/CONTEXT.md` serve as:
- Cross-agent signal passing
- Locked decisions registry
- Open questions tracker
- Blocker documentation

**NOT affected by T356** - CONTEXT.md is a project coordination file, not a prompt injection mechanism. The `## CONTEXT` section in user messages pulls dynamic runtime data (tasks, hub messages), not CONTEXT.md file content.
