# URL-Based Project Routing Specification

## Overview

Enable multi-project support via URL parameter `?project=<project_id>` for stateless server access across multiple devices and future cloud deployment.

---

## URL Structure

### Format
```
http://localhost:8000/?project=P001
http://localhost:8000/studio.html?project=P001
wss://localhost:8000/ws?project=P001
```

### Parameter
| Param | Format | Example | Default |
|-------|--------|---------|---------|
| `project` | Project ID | `P001` | `null` (no project) |

### Validation
- Pattern: `/^P\d{3,}$/` (P followed by 3+ digits)
- Invalid ID → 400 Bad Request with `{"error": "Invalid project ID format"}`
- Non-existent ID → 404 Not Found with `{"error": "Project not found"}`

---

## API Parameter Passing

### REST Endpoints
All `/api/*` endpoints accept optional `?project=` query parameter:

```
GET  /api/history?project=P001
GET  /api/tasks?project=P001
POST /api/tasks?project=P001
GET  /api/projects/P001/document/white_paper
```

### WebSocket
Project ID passed on connection, persists for session:

```javascript
// Frontend connects with project ID
const ws = new WebSocket(`ws://localhost:8000/ws?project=${projectId}`);
```

Server extracts from query string, stores in connection state:
```python
@app.websocket("/ws")
async def ws_endpoint(websocket: WebSocket):
    project_id = websocket.query_params.get("project")
    # Validate and bind to connection
```

### Request Header (Alternative)
For tools/scripts that can't easily modify URLs:
```
X-Project-ID: P001
```
Priority: Query param > Header > Active project from session

## Data Isolation Boundaries

### Per-Project Storage (Isolated)
```
projects/<project_id>/
├── memory/              # AC-Memory tiers (tier_0.json, tier_1.json, ...)
├── history/             # History narratives (drafts/, chapters/, ...)
├── CONTEXT.md           # Cross-agent signals
├── deliverables/        # Task outputs (T###.md)
└── logs/                # Message logs (YYYY-MM-DD.json)
```

### Shared (Global)
```
data/
├── tasks.json           # Task queue (all projects)
├── tasks_archive.json   # Completed tasks
├── projects.json        # Project registry
├── metrics/             # Token usage, skill usage
└── suggestions/         # Learning system

studio/
├── agents/              # Agent configs/roles
└── skills/              # Skill library
```

### Decision Rationale

| Data Type | Scope | Reason |
|-----------|-------|--------|
| Memory tiers | Project | Context is game-specific |
| History narratives | Project | Chronicles project evolution |
| CONTEXT.md | Project | Cross-agent signals are project-scoped |
| Deliverables | Project | Task outputs belong to project |
| Task queue | Shared | Agent fleet serves all projects |
| Suggestions | Shared | Process improvements apply globally |
| Agent configs | Shared | Same agents, different contexts |

## Backward Compatibility

### Single-Project Mode
When no `?project=` parameter is provided:
1. Use `project_manager.active_project_id` if set
2. Fall back to `data/` paths (legacy mode)

### Existing Endpoints
All current endpoints continue working unchanged:
- `GET /api/history` → uses active project or default
- `GET /api/history?project=P001` → uses specified project

### Migration Path
1. **Phase 1**: Add `?project=` support to all endpoints (additive)
2. **Phase 2**: Frontend reads project from URL on load
3. **Phase 3**: Deprecate server-side active_project_id (optional)

## Frontend Integration

### URL Reading on Load
```javascript
// studio.js - on page load
const urlParams = new URLSearchParams(window.location.search);
const projectId = urlParams.get('project');
if (projectId) {
    await setActiveProject(projectId);
}
```

### Navigation Updates
```javascript
function setActiveProject(projectId) {
    const url = new URL(window.location);
    if (projectId) {
        url.searchParams.set('project', projectId);
    } else {
        url.searchParams.delete('project');
    }
    window.history.pushState({}, '', url);
}
```

## Cloud Deployment Considerations

### Stateless Server
- No server-side session state
- Project context derived entirely from request parameters
- Each request is independent

### Multi-Device Access
- Same URL opens same project on any device
- No cross-device sync needed (project ID is in URL)
- Concurrent access from multiple devices supported

### Path Resolution
```python
# Server must resolve project paths dynamically per-request
def get_project_path(request: Request) -> Path:
    project_id = request.query_params.get("project")
    if project_id:
        return PROJECTS_DIR / project_id
    return DATA_DIR
```

## Edge Cases

| Scenario | Behavior |
|----------|----------|
| Invalid project ID format | 400 Bad Request |
| Non-existent project ID | 404 Not Found |
| Archived project ID | 403 Forbidden (unless `?include_archived=true`) |
| Missing project param | Use active project or default |
| Project folder missing | Create on first write |
