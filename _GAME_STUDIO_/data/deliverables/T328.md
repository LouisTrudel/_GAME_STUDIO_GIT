### Edge Cases Verified

| Scenario | Result |
|----------|--------|
| Empty `?project=` | Falls back to default |
| Invalid project ID in URL | `setActiveProject` fails gracefully, stays on current |
| Project archived via URL | `set_active` returns False (archived check in `project_manager.set_active`) |
| Message sent with different project context | `websocket.py:70-71` switches context dynamically |

### Minor Observations (Non-Blocking)

1. **No URL validation on frontend**: `getUrlProjectId()` returns raw param without checking if project exists. Backend handles this gracefully, but could log a warning.

2. **Console logging verbosity**: Lines like `studio-core.js:121` log every connection attempt. Consider reducing in production.

3. **Race condition potential**: If user rapidly switches projects via dropdown AND URL changes simultaneously, last write wins. Acceptable behavior.
