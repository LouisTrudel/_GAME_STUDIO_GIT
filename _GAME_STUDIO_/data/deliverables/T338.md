## 3. Making "One-Prompt" Work: What Makes a Good Spec

### The 3-Part Formula (show to user)

> **"A good spec answers: What does the player DO? What do they SEE? What do they FEEL?"**

### Good Spec Checklist

| Element | Example | Why It Matters |
|---------|---------|----------------|
| Core action | "Players jump between platforms" | Defines gameplay |
| Win/lose condition | "Fall off = game over" | Defines loop |
| Visual style | "Bright colors, cartoon style" | Guides art |
| Key features | "Double jump, coins, leaderboard" | Scopes work |
| Mood | "Relaxing, no time pressure" | Sets tone |

### Example: Weak vs. Strong

**Weak:** "Make a fun platformer game"

**Strong:** "A platformer where you jump between floating islands. Collect stars to unlock new levels. Peaceful music, soft pastel colors. No enemies—just tricky jumps. Mobile-friendly controls."

### Prompt Enhancement UI

If spec is too vague, show:
```
Your idea is clear, but a few details would help:
- What happens when the player wins or loses?
- Any preference on visual style? (realistic, cartoon, pixel art)
- Should there be a timer, score, or other challenge?
```

## 4. Error States & Recovery

### Error: Spec Too Vague

**Message:** "We need a bit more detail to get started."

**Recovery:** Show fill-in-the-blank template:
```
I want to make a [genre] game where the player [core action].
The goal is to [win condition].
It should look [visual style] and feel [mood].
```

---

### Error: Conflicting Requirements

**Message:** "We noticed some things that might conflict."

**Example:**
> "You asked for 'relaxing gameplay' but also 'intense time pressure.' Which matters more?"

**Buttons:** `Relaxing` | `Intense` | `Somewhere in between`

---

### Error: Build Failed

**Message:** "Something went wrong while building. Our team is looking into it."

**Show:** Simplified error (not technical), retry button.

**Example:**
```
[!] The coin collection system hit a snag.
    We're adjusting and trying again.
    
    [Retry Automatically] [Contact Support]
```

---

### Error: Scope Too Large

**Message:** "This project is ambitious! Let's start with the core and add features after."

**Recovery:** Show prioritized feature list, let user check what's essential for V1.

## 5. Tone Guidelines

| Do | Don't |
|----|-------|
| "We're building your game" | "The AI agents are processing" |
| "Something needs your attention" | "Error: validation failed" |
| "Ready in a few minutes" | "Estimated completion: 4m 32s" |
| "Let's fix this together" | "Invalid input" |

---

## Summary

The path to one-prompt success:

1. **Good input prompts** that teach by example
2. **Confirmation step** before building starts
3. **Visible progress** during build (no black box)
4. **Graceful errors** that guide, not block
5. **Human language** throughout—no tech jargon
