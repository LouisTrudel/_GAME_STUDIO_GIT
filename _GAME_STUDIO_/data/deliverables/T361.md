# LLM Token I/O Ratio Research

## Summary
Output tokens cost 3-8× more than input tokens (median 4×), making output length the primary cost driver. Effective context utilization sits at 60-70% of advertised maximums, with practical sweet spots at 128K for most tasks. Extended thinking should be reserved for complex multi-step reasoning—it can consume 3-10× standard token counts.

## Key Findings

| Finding | Evidence | Implication |
|---------|----------|-------------|
| Output tokens 3-8× more expensive than input | [Silicon Data](https://www.silicondata.com/blog/llm-cost-per-token), [Morph](https://www.morphllm.com/llm-context-window-comparison) | Constrain output lengths aggressively |
| Effective context = 60-70% of advertised max | [Elvex benchmark](https://www.elvex.com/blog/context-length-comparison-ai-models-2026) | Plan around effective, not marketed capacity |
| Extended thinking uses 3-10× tokens | [TokenRate](https://tokenrate.dev/blog/providers/claude-extended-thinking-cost-analysis), [Developers Digest](https://www.developersdigest.tech/blog/extended-thinking-claude-production-guide) | Reserve for high-stakes reasoning only |
| Median coding output: 252 tokens (Claude) | [TraceLab research](https://arxiv.org/pdf/2606.30560) | Most tasks don't need large output caps |
| 128K = practical sweet spot for debugging | [DevTk](https://devtk.ai/en/blog/llm-context-window-explained/) | Balance capability vs. infrastructure cost |

## Task-Type Breakdown

| Task Type | Recommended Context | Expected Output | I/O Ratio | Notes |
|-----------|-------------------|-----------------|-----------|-------|
| **Coding** | 10-50K tokens (target files + deps) | 200-500 tokens | 20:1 - 100:1 | Keep files <600 lines, functions <56 lines for best results |
| **Debugging** | 30-80K tokens (broader context) | 300-800 tokens | 40:1 - 100:1 | Include stack traces, related modules |
| **Writing** | 5-20K tokens (source material) | 500-2000 tokens | 5:1 - 20:1 | Higher output needs than analysis tasks |
| **Analysis** | 20-60K tokens (data + docs) | 300-1000 tokens | 20:1 - 60:1 | Structure output with explicit constraints |
| **Summarization** | 2-10K tokens (source document) | 100-300 tokens | 10:1 - 50:1 | Most efficient task type by ratio |

## Extended Thinking vs Standard Mode

| Use Extended Thinking | Use Standard Mode |
|-----------------------|-------------------|
| Multi-step reasoning (math proofs, complex algorithms) | Summarization, formatting |
| Ambiguous/contradictory inputs | Factual Q&A |
| High-stakes decisions (risk analysis) | First drafts, brainstorming |
| Inconsistent prior results | Code reviews (routine) |
| Budget: Complex debugging | Budget: Syntax fixes |

**Cost control**: Use `budget_tokens` parameter to cap thinking—provides 40-60% cost reduction on agent workloads.

## Analysis

**Alternative 1: Maximize context window usage**
- Load entire codebases, hope model finds relevant pieces
- Costs more, accuracy degrades after 50-70% of window used
- ❌ Not recommended

**Alternative 2: Minimal context, iterate**
- Small prompts, multiple round-trips
- Higher latency, loses coherence across turns
- ⚠️ Sometimes necessary, not optimal

**Alternative 3: Task-specific context budgets (Recommended)**
- Calculate context needs per task type
- Set explicit output constraints
- Use prompt caching for repeated patterns
- ✅ Best balance of cost, quality, latency

## Recommendations

| Priority | Action | Rationale |
|----------|--------|-----------|
| 1 | **Set explicit output length constraints** | "Answer in 50 words" + max_tokens cap—prevents unbounded output costs |
| 2 | **Use Sonnet for coding, reserve Opus for architecture** | Sonnet benchmarks close to Opus at 60% cost |
| 3 | **Enable prompt caching** | Eliminates 500-2000 tokens of repeated context per session |
| 4 | **Use /compact at ~15K tokens** | Compresses 10-20K down to 1-3K without quality loss |
| 5 | **Budget extended thinking** | Set `budget_tokens`; default max wastes 40-60% on routine reasoning |
| 6 | **Route by task complexity** | Summarization/formatting → Haiku; Coding → Sonnet; Architecture → Opus |

## Studio Fleet Specifics

For your agent fleet:
- **Boss agent**: Standard mode for orchestration, extended thinking only for strategic decisions
- **Context agent**: Never needs extended thinking—research/extraction tasks
- **Research agents**: Standard mode default; extended for synthesizing contradictory sources
- **Session memory**: Compress aggressively; context history bloats fast

Target daily API spend: **$5-15/developer** with good habits vs. $20-40 without.
