## === T262 DELIVERABLE: QA Tools Parameter Handling Fix ===

**Fixed:** `studio/agents/qa/tools.py:41-61, 130-143`

### Changes Made

**1. `report_bug()` (line 41)**
- Made `assignee` optional with default `"Programmer"`
- Added `**kwargs` to absorb unexpected parameters
- Maps `steps` → `description` when passed

**2. `test_summary()` (line 130)**
- Made `passed` optional with default `None`
- Added `**kwargs` to absorb unexpected parameters
- Maps `failed` → inverse of `passed` (failed=True → passed=False)
- Defaults to passed=True if neither specified

### Both Parameter Styles Now Work

```python
# Standard params
report_bug(title='Bug', assignee='Programmer', description='Details')

# Alternate params (now works)
report_bug(title='Bug', steps='1. Do this 2. See error')
report_bug(title='Bug')  # defaults assignee to Programmer

# Standard params
test_summary(task_id='T001', passed=True, summary='OK')

# Alternate params (now works)
test_summary(task_id='T001', failed=True, summary='Issues found')
test_summary(task_id='T001', failed=False, summary='All good')
```

### Schema Note
The schemas (`REPORT_BUG_SCHEMA`, `TEST_SUMMARY_SCHEMA`) still document the preferred parameter names. The `**kwargs` handling provides backward compatibility with alternate parameter names used by some agents.
