## === Tiered Memory File Structure & Schema ===

### Overview

4-tier progressive compression system inspired by human memory consolidation. Each tier trades detail for density, keeping what matters.

---

### Tier Architecture

| Tier | Name | Retention | Location | Purpose |
|------|------|-----------|----------|---------|
| T0 | Hot | Current session | `data/session_memory.md` | Immediate context, full detail |
| T1 | Warm | Last 7 days | `data/memory/warm.json` | Recent tasks, key outputs |
| T2 | Cool | Last 30 days | `data/memory/cool.json` | Summaries, patterns, outcomes |
| T3 | Cold | 30+ days | `data/memory/cold.json` | Semantic index only |

---

### File Paths

```
data/
├── session_memory.md          # T0: Current session (human-readable)
├── memory/
│   ├── warm.json              # T1: Recent history
│   ├── cool.json              # T2: Compressed summaries
│   ├── cold.json              # T3: Semantic index
│   └── archive/               # Raw backup (safety net)
│       └── YYYY-MM.json       # Monthly raw archives
```

---

### Threshold Triggers

| Transition | Trigger | Batch Size |
|------------|---------|------------|
| T0 → T1 | Session end OR session_memory.md > 50 lines | All T0 content |
| T1 → T2 | Entry age > 7 days OR warm.json > 500KB | Entries older than 7d |
| T2 → T3 | Entry age > 30 days OR cool.json > 200KB | Entries older than 30d |
| T3 → Archive | Entry age > 90 days | Monthly batch to archive/ |

---

### Schema Per Tier

#### T0: Hot (session_memory.md)
```markdown
# Session Memory

## Active Context
- [freeform bullets, max 10 items]

## Work Accomplished
- [task summaries with IDs]

## Friction Events
- [blockers, errors, surprises]

## User Intent
- [what human wants, inferred goals]
```
**Compression:** None (full detail)

---

#### T1: Warm (warm.json)
```json
{
  "updated": "2026-09-06T22:41:00Z",
  "entries": [
    {
      "date": "2026-09-06",
      "tasks": ["T234", "T235", "T236"],
      "summary": "Archive compression implemented",
      "outcomes": ["97.2% size reduction", "to_archive_dict() method added"],
      "agents": ["programmer", "qa"],
      "tags": ["optimization", "data"]
    }
  ]
}
```
**Compression:** Group by day, extract outcomes, drop raw outputs  
**Size target:** ~1KB per day

---

#### T2: Cool (cool.json)
```json
{
  "updated": "2026-09-06T22:41:00Z",
  "weeks": [
    {
      "week": "2026-W36",
      "theme": "System optimization sprint",
      "key_outcomes": [
        "Archive compression: 97% reduction",
        "Prompt injection order: tools→role→skills"
      ],
      "patterns": ["Boss delegation friction", "Schema migrations"],
      "task_count": 15,
      "agents_active": ["programmer", "designer", "qa"]
    }
  ]
}
```
**Compression:** Aggregate to weeks, extract themes/patterns, drop individual tasks  
**Size target:** ~200 bytes per week

---

#### T3: Cold (cold.json)
```json
{
  "updated": "2026-09-06T22:41:00Z",
  "index": [
    {
      "month": "2026-09",
      "keywords": ["archive", "compression", "memory", "schema", "delegation"],
      "capabilities_gained": ["compressed task storage", "tiered memory"],
      "lessons": ["Delegation > direct implementation for Boss"],
      "task_count": 45
    }
  ]
}
```
**Compression:** Monthly semantic index only—keywords for retrieval, lessons for behavior  
**Size target:** ~100 bytes per month

### Compression Ratios (Expected)

| Tier | Raw Equivalent | Compressed | Ratio |
|------|----------------|------------|-------|
| T0 → T1 | ~10KB/day | ~1KB/day | 10:1 |
| T1 → T2 | ~7KB/week | ~200B/week | 35:1 |
| T2 → T3 | ~800B/month | ~100B/month | 8:1 |
| **Total** | ~300KB/month raw | ~1.5KB/month cold | **200:1** |

---

### Edge Cases

| Scenario | Behavior |
|----------|----------|
| Session crash before T0→T1 | Recover from raw logs in `data/logs/` |
| Search hits cold tier only | Return keywords + month, suggest loading warm/archive if detail needed |
| Memory query spans tiers | Merge results: T0 full + T1 summary + T2/T3 keywords |
| Schema migration needed | Archive/ preserves raw format for reprocessing |

---

### Access Patterns

| Query Type | Tier(s) | Response |
|------------|---------|----------|
| "What did I do today?" | T0 | Full session_memory.md |
| "Last week's tasks" | T1 | Warm entries, full outcomes |
| "How did we solve X?" | T1 + T2 | Search outcomes + patterns |
| "Have we done Y before?" | T2 + T3 | Keyword match, return context |

---

### Success Criteria

- T0 stays under 50 lines (agent context window friendly)
- T1 stays under 500KB (1 year = ~365KB at 1KB/day)
- T2 stays under 50KB (5 years = ~52KB at 200B/week)
- T3 stays under 10KB (8 years = ~9.6KB at 100B/month)
- Cold tier keyword search < 50ms
- No data loss—archive/ preserves raw for reconstruction

---

### Implementation Notes

1. **Consolidation process** runs at session end (T0→T1) and daily cron (T1→T2→T3)
2. **Reconstruction** possible: T3 keywords → find in archive/ → expand to full detail
3. **Salience scoring** for T2→T3: keep entries with high task count, friction, or explicit "lesson learned" tags
4. **Archive/ backup** is write-only append, never compressed—safety net during refinement

---

**Rationale:** This mirrors human memory—vivid recent experiences (T0/T1) compress into patterns and lessons (T2/T3), with raw material (archive/) available for reconstruction when needed. The 4-tier structure maps to natural time boundaries (session/week/month/quarter).
