# T626 - Main View 50%-50% Layout Fix

## Problem
The main view was showing a 50%-50% split with both Hub and Agents panels visible side-by-side, even though only one tab should be active at a time.

## Root Cause
CSS specificity issue in `studio.css:1656`:

```css
.agents-panel {
    display: flex;  /* ← THIS WAS THE BUG */
    flex-direction: column;
    height: 100%;
}
```

The `.agents-panel` rule had `display: flex` which **overrode** the base `.panel { display: none; }` rule for inactive panels.

## How Tab System Should Work

### HTML Structure (studio.html)
```html
<nav class="tabs">
    <div class="tab active" data-tab="hub">Hub</div>
    <div class="tab" data-tab="agents">Agents</div>
    <!-- ... other tabs ... -->
</nav>

<div class="main">
    <div class="panel hub-panel active" id="panel-hub">...</div>
    <div class="panel agents-panel" id="panel-agents">...</div>
    <!-- ... other panels ... -->
</div>
```

### CSS Rules (studio.css)
```css
.main {
    flex: 1;
    display: flex;      /* Container uses flexbox */
    overflow: hidden;
}

.panel {
    display: none;      /* ALL panels hidden by default */
    flex: 1;
    overflow: hidden;
}

.panel.active {
    display: flex;      /* Only active panel shown */
}
```

### Tab Switching Logic (studio-core.js:297-305)
```javascript
document.querySelectorAll('.tab').forEach(tab => {
    tab.addEventListener('click', () => {
        // Remove active from all tabs and panels
        document.querySelectorAll('.tab').forEach(t => t.classList.remove('active'));
        document.querySelectorAll('.panel').forEach(p => p.classList.remove('active'));
        
        // Add active to clicked tab and corresponding panel
        tab.classList.add('active');
        document.getElementById(`panel-${tab.dataset.tab}`).classList.add('active');
    });
});
```

## The Bug Explained

**CSS Specificity:**
- `.panel { display: none; }` - Base rule (specificity: 0,1,0)
- `.agents-panel { display: flex; }` - Specific rule (specificity: 0,1,0)

Both have **equal specificity**, so the one defined **last** wins. Since `.agents-panel` appears after `.panel` in the CSS file, its `display: flex` overrode the `display: none`, causing the agents panel to always be visible.

**Result:** Both hub panel and agents panel were visible simultaneously, creating the 50%-50% split.

## The Fix

**File:** studio.css:1655-1658

**Before:**
```css
.agents-panel {
    display: flex;      /* ← Removed this line */
    flex-direction: column;
    height: 100%;
}
```

**After:**
```css
.agents-panel {
    flex-direction: column;
    height: 100%;
}
```

**Why This Works:**
- `.panel { display: none; }` now applies to `.agents-panel` when inactive
- `.panel.active { display: flex; }` applies when the Agents tab is clicked
- The `flex-direction: column` property still applies when the panel becomes active (since display and flex-direction are separate properties)

## Verification

### Expected Behavior
1. Only Hub panel visible by default (has `active` class)
2. Clicking Agents tab:
   - Removes `active` from Hub panel → `display: none`
   - Adds `active` to Agents panel → `display: flex` + `flex-direction: column`
3. Only one panel visible at a time

### Test Cases
- ✅ Hub tab active: Only hub panel visible
- ✅ Agents tab active: Only agents panel visible with terminal dock
- ✅ Other tabs: Corresponding panels show exclusively
- ✅ No 50-50 split in any state

## Additional Context

The same issue could have occurred with other panel-specific styles, but `.agents-panel` was the only one that explicitly set `display: flex` at the panel level rather than relying on `.panel.active`.
