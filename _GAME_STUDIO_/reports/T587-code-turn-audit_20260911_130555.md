## The "Gibberish" Problem

### What's Actually Happening

The deliverables contain run-on thinking text like:

```
I'll investigate the deliverable display issue in the Hub interface.Now let me check the 
memory loading to see if deliverables are being loaded into t0:Let me search for where 
deliverables might be loaded:Let me check the hub.py to see how messages are added to t0:
```

**Analysis:**
- 7 "Let me" phrases in T578
- 10 "Let me" phrases in T583
- Missing line breaks between thought steps
- Stream-of-consciousness output captured verbatim

### Root Cause

The persistent Claude CLI backend captures ALL agent output, including thinking text that should be formatted with line breaks. The agent is exploring the codebase (search_code, read_lines) and narrating its investigation, but the formatting is lost in the deliverable.

## Root Cause: Deliverable Formatting, Not Turn Issues

### The Real Problem

The agent output lacks formatting breaks. Compare:

**Current (broken):**
```
I'll investigate.Now let me check:Let me search:
```

**Expected:**
```
I'll investigate.

Now let me check:

Let me search:
```

### Where It Breaks

Location: **backends/backends/persistent_claude_cli.py** or **studio/core/file_tools.py**

The deliverable save process captures raw agent output without preserving formatting. The agent IS producing line breaks during execution, but they're lost when saving to markdown.
